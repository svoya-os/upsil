# UpsiL на деле: что было удобно, что мешало и что изменилось в 0.3

Чтобы понять, хорош ли UpsiL для работы с нейросетями, на версии 0.2 написали четыре
программы — такие, какие действительно пишут, когда работают с моделями, — и честно
записали, где язык помогал, а где приходилось бороться. Версия 0.3 — ответ на эти записи.

| Программа | Что делает | 0.2 | 0.3 |
|---|---|---|---|
| Спирали ([examples/spirals.upl](../examples/spirals.upl)) | учит нейросеть на PyTorch различать две спирали, считает точность на отложенных точках | 76 строк кода | 31 строка |
| Разметка отзывов ([examples/reviews.upl](../examples/reviews.upl)) | модель ставит каждому отзыву метку и оценку, результат — в CSV | 24 строки, падала на пятом отзыве и теряла всё | 16 строк, переспрашивает модель и не падает |
| Сравнение промптов ([examples/prompt_eval.upl](../examples/prompt_eval.upl)) | прогоняет набор вопросов через несколько шаблонов промпта и печатает таблицу | 25 строк, запросы по одному | 23 строки, запросы параллельно |
| Вопросы к заметкам ([examples/rag_notes.upl](../examples/rag_notes.upl)) | ищет по папке заметок и отвечает по найденному | работала хорошо | без изменений |

Нейросети в этих проверках действительно обучались: PyTorch в тестах заменяет небольшой
автоградиент на numpy (`tests/microtorch.py`), его градиенты сверены с численными.

## Что было удобно — и осталось как есть

- **Оператор промпта** `[m] => "..."` и `-> json`: вопрос модели читается как обычное
  выражение, без клиентов, запросов и разбора ответа.
- **`vector_store` и `db.context(вопрос)`**: поиск по заметкам — пять строк; если сервер не
  умеет эмбеддинги, поиск сам переходит на слова.
- **Блок `model`**: слои — поля, `forward` — метод, регистрация слоёв и `super().__init__()`
  не нужны.
- **`nn.X`** находит имя в `torch.nn`, `torch.nn.functional` или `torch` — не нужно помнить,
  где лежит `relu`, а где `Linear`.
- **Многострочные промпты** с автоматическим выравниванием и интерполяцией `{...}`.
- **Ошибки до запуска**: опечатка в имени переменной находится компилятором с подсказкой
  «может быть, 'limit'?», а ошибки выполнения показываются по строкам `.upl`, без
  внутренностей Python.

## Что мешало — и что сделано

**1. Один кривой ответ модели ронял всю программу.** Разметка отзывов остановилась на пятом
отзыве: модель ответила «Конечно! Этот отзыв скорее положительный» вместо JSON, `-> json`
бросил ошибку, и четыре уже размеченных отзыва пропали — поймать ошибку было нечем.

Сделано: `try`/`catch`/`finally`/`throw`; форма ответа `-> json({"label": ["pos", "neg",
"neu"], "score": float})`, которая проверяет ответ и при ошибке объясняет модели, что не так,
и спрашивает ещё раз; серверам, умеющим ограничивать вывод (llama.cpp, OpenAI), форма
передаётся как JSON Schema. Ошибка, если модель так и не ответила по форме, —
`llm.FormatError`, которую можно поймать. Для пачек вопросов — `m.ask_all(..., errors =
"null")`: плохой ответ становится `null`, остальные сохраняются.

**2. `torch.no_grad()` нельзя было использовать.** Для оценки модели пришлось вручную
выключать и включать градиенты через `set_grad_enabled` — а если между ними случалась ошибка,
градиенты так и оставались выключенными.

Сделано: `with nn.no_grad() { ... }` и любые контексты `with ... as x { }`; плюс
`nn.evaluating(net)` — режим оценки и без градиентов, с возвратом прежнего режима.

**3. Столбцы данных собирались циклами.** Чтобы получить признаки и метки из списка точек,
понадобились две функции по пять строк.

Сделано: генераторы списков и словарей — `nn.tensor([[p[0], p[1]] for p in rows])`,
`{w: len(w) for w in words}`, `sum(x * x for x in xs)`.

**4. Сортировка и шаблоны промптов требовали отдельных функций.** `sorted(..., key = ...)`
принимал только именованную функцию, а хранить шаблоны промптов как данные было нельзя:
строка подставляет значения сразу.

Сделано: лямбды — `sorted(rows, key = r => r["score"])`, `{"коротко": q => "Ответь
одним словом: {q}"}`.

**5. Цикл обучения — одно и то же каждый раз.** Эпохи, перемешивание, мини-пакеты через
`randperm` и срезы с `div(len + batch - 1, batch)`, перенос на устройство, подсчёт точности —
около тридцати строк.

Сделано: `nn.fit(net, x, y, epochs = 60, val = (x_test, y_test))` со строкой прогресса и
историей обучения (Ctrl-C останавливает досрочно, выученное сохраняется), `nn.batches`,
`nn.accuracy`, `nn.auto_device()` (cuda, mps или cpu), `nn.count_params`.

**6. Нет значения по условию.** `var device = "cpu"` плюс `if` на три строки, а для
аргумента командной строки по умолчанию — вспомогательная функция, которую ещё и нельзя было
вызвать до её объявления.

Сделано: `val source = if (len(sys.args) > 0) sys.args[0] else "reviews.csv"`.

**7. Нельзя вернуть несколько значений и разложить их.** `split(data)` возвращал список, из
которого доставали `[0]` и `[1]`.

Сделано: кортежи и распаковка — `return train, test`, `val (train, test) = split(data)`,
`a, b = b, a`.

**8. Регулярные выражения почти невозможно было записать.** `"\d+"` — ошибка компиляции
(неизвестная escape-последовательность), а `{2}` в шаблоне молча превращался в подстановку
числа.

Сделано: сырые строки `r"\d{2}"` и модуль `re` (`test`, `find`, `find_all`, `groups`,
`replace` — в том числе с лямбдой, `split`).

**9. Данные для обучения обычно лежат в CSV.** Приходилось подключать `import py "csv"` и
писать обвязку.

Сделано: модуль `csv` — `csv.read("data.csv", numbers = true)` возвращает список словарей с
числами, `csv.write(...)` пишет обратно.

**10. Программа из нескольких файлов.** Подготовку данных и обучение хочется держать
отдельно, но импорта своих файлов не было.

Сделано: `import "data.upl"` и `import helpers` (файл рядом с программой); каждый файл
выполняется один раз, циклы импорта обнаруживаются.

**11. Негде проверить, что всё работает.** Ни `assert`, ни способа запустить проверки.

Сделано: `assert условие, "сообщение"` (работает и под `python -O`) и `upsil test` — функции
`test_...` в файлах `test_*.upl`, с отчётом по каждой и строкой, где не прошло.

## Второй раунд: программы на 0.3

На готовой 0.3 написали ещё две программы: классификатор отзывов «мешок слов + MLP» из CSV
(словарь, кодирование, обучение через `nn.fit`, самые «позитивные» слова, проверка на новых
фразах) и планировщик, где модель составляет план по форме
`{"steps": [{"tool": ["calc", "note"], "input": str}]}`, а программа выполняет шаги. Обе
получились короткими и читаемыми; вложенная форма поймала выдуманный моделью инструмент
`"calculator"`, и повторный вопрос указал точное место: `steps[0].tool`. Нашлось и
исправлено ещё три вещи:

- **`r["text"]`, `a["label"]` на каждом шагу.** Строки CSV и ответы модели теперь *записи*:
  `r.text`, `plan.steps[0].tool`; квадратные скобки тоже работают, а опечатка в поле
  сообщает, какие поля есть.
- **`if (a > b) "a" else "b"` в REPL был ошибкой**: строка, начинающаяся с `if`, считалась
  инструкцией. Теперь это значение (и в файле — инструкция-выражение), а `if (c) { ... }`
  остаётся обычным `if`.
- **Лямбда, созданная в `catch (e)`, теряла `e`**, если её вызывали позже: так устроен Python.
  Теперь пойманная ошибка живёт, пока она нужна.

## Что осталось на следующие версии

- **Наследование классов и моделей** (`class B : A`) — пригодится для своих типов ошибок и
  общих частей моделей.
- **Функции с блоком как выражение** (`fun (x) { ... }`) — сейчас лямбда умещается в одно
  выражение, для большего нужна именованная функция.
- **`?.` и `?:`** — безопасный доступ к полям ответа модели, где поле может отсутствовать.
- **Кэш ответов модели** — чтобы при отладке программы не спрашивать модель заново.
- **Форматирование кода (`upsil fmt`) и языковой сервер** — подсказки и ошибки прямо в
  редакторе.

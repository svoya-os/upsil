## 1. Обзор

UpsiL — небольшой язык для скриптов, которые работают с языковыми моделями, поиском по
документам и нейросетями. Синтаксис похож на Kotlin (`fun`, `val`/`var`, `for (i in 0..n)`),
а программа компилируется в модуль Python: компилятор строит дерево Python (модуль `ast`) и
выполняет его. Поэтому:

- типизация во время выполнения динамическая, как в Python; аннотации типов записываются,
  а `upsil check` проверяет только очевидные несовпадения литералов;
- любую библиотеку Python можно подключить явно: `import py "numpy" as np`;
- `upsil build` показывает читаемый код Python, в который превращается программа.

Файл программы имеет расширение `.upl` и кодировку UTF-8. Программа выполняется сверху вниз;
обязательной функции `main` нет (принято объявлять `fun main()` и вызывать её в конце файла).

```upsil
val name = "UpsiL"
fun greet(who) {
    return "Привет, {who}!"
}
print(greet(name))
```
```output
Привет, UpsiL!
```

## 2. Лексика

### 2.1. Текст программы и комментарии

Исходный текст — UTF-8; метка BOM в начале допускается, переводы строк `\r\n` и `\r`
считаются `\n`.

Комментарии: `//` до конца строки и `/* ... */`, которые могут быть вложенными. Комментарий
`/* */`, внутри которого есть перевод строки, действует как перевод строки.

```upsil
// строчный комментарий
/* блочный /* вложенный */ комментарий */
print(1) // после кода
```
```output
1
```

### 2.2. Конец инструкции

Инструкция заканчивается переводом строки. Перевод строки **не** заканчивает инструкцию:

1. внутри круглых `( )` и квадратных `[ ]` скобок;
2. внутри фигурных скобок словаря `{ }` (в блоке кода `{ }` перевод строки, наоборот,
   разделяет инструкции);
3. если строка заканчивается оператором, которому нужен правый операнд: `+ - * / % @ ** ==
   != < <= > >= = += -= *= /= %= .. ..= => -> , : .` или словом `and`, `or`, `not`, `in`;
4. если следующая строка начинается с точки `.` (цепочка вызовов).

Кроме того, перевод строки допускается перед `{`, открывающей блок, и перед `else`.
Вместо перевода строки можно поставить `;`. После `}` составной инструкции (`fun`, `if`,
`while`, `for`, `class`, `model`) следующая инструкция может идти на той же строке.

```upsil
val total = 1 +
    2 +
    3
val words = ["один",
             "два"]
val text = "  Привет, Мир  "
    .strip()
    .lower()
print(total, words, text); print("готово")
val x = 5
-3
print(x)
```
```output
6 ["один", "два"] привет, мир
готово
5
```

В последнем примере `-3` — отдельная инструкция: перевод строки после `val x = 5` закончил
объявление.

### 2.3. Имена

Имя начинается с буквы или `_` и состоит из букв, цифр и `_`. Буквы могут быть любыми
буквами Юникода (`val имя = 1`); имена нормализуются по NFKC, как в Python. Регистр важен.

Зарезервированы и не могут быть именами:

- ключевые слова UpsiL (2.4);
- ключевые слова Python, которые не являются ключевыми словами UpsiL:
  `False None True async await def del elif except from global is lambda nonlocal pass raise
  yield` — программа компилируется в Python;
- `self` и `super` (их нельзя объявить);
- имена, начинающиеся с `_upsil` (служебные имена компилятора).

### 2.4. Ключевые слова

Всегда ключевые слова:

```text
if else while for return break continue
try catch finally throw with assert
fun val var class import as
and or not in
true false null
```

Контекстные слова особенные только в одном месте, а в остальных случаях — обычные имена
(например, `val model = 1` допустимо):

| Слово | Особое значение |
|---|---|
| `model` | `model Имя { ... }` — объявление модели (раздел 8.2) |
| `graph` | `graph forward(x) { ... }` — метод внутри `model` |
| `llm` | `llm m = ...` — объявление модели ИИ (9.1) |
| `vector_store` | `vector_store db = ...` — объявление хранилища (9.3) |
| `py` | `import py "numpy"` — импорт модуля Python |
| `json` | `[m] => "..." -> json` — ответ модели в JSON |

### 2.5. Числа

- Целые: `42`, `1_000_000`, `0xFF`, `0b1010`, `0o755`. Знак `_` разделяет разряды.
- Дробные: `3.14`, `1e-3`, `2.5E+2`. Точка должна стоять между цифрами, поэтому `0..5` —
  это диапазон, а не число.
- Минус перед числом — это унарный оператор.

### 2.6. Строки

Строка пишется в двойных кавычках `"..."` и занимает одну строку текста. Одинарных кавычек
в UpsiL нет.

Escape-последовательности:

| Запись | Символ |
|---|---|
| `\n` `\t` `\r` `\0` | перевод строки, табуляция, возврат каретки, нулевой символ |
| `\"` `\'` `\\` | кавычка, апостроф, обратная косая черта |
| `\{` `\}` | фигурные скобки |
| `A`, `\u{1F600}` | символ Юникода по коду (4 или 1–6 шестнадцатеричных цифр) |

Любая другая последовательность `\x` — ошибка компиляции.

**Интерполяция.** `{выражение}` внутри строки вставляет значение выражения, показанное так
же, как его печатает `print` (раздел 4.9). Внутри скобок — обычное выражение UpsiL: оно
разбирается и проверяется компилятором (неизвестные имена — ошибка компиляции) и никогда не
выполняется как текст. Внутри можно использовать строки: `"{d["ключ"]}"`. После двоеточия
можно указать формат, как в Python: `{x:.2f}`, `{name:<10}`; с форматом значение
форматируется средствами Python (`format(x, ".2f")`).

Чтобы написать фигурную скобку, экранируйте её: `\{` и `\}`. Одиночная `}` допустима и так.
Пустые `{}` — ошибка.

```upsil
val name = "Макс"
val pi = 3.14159
print("Привет, {name}! {1 + 2} {[1, "a"]} {pi:.2f}")
print("JSON: \{\"a\": 1\}")
```
```output
Привет, Макс! 3 [1, "a"] 3.14
JSON: {"a": 1}
```

Значения, которые попадают в строку во время выполнения, вставляются как есть: фигурные
скобки в данных остаются просто символами.

**Многострочные строки** `"""..."""` удобны для промптов. Внутри них можно писать `"` без
экранирования; интерполяция и escape-последовательности работают. Если сразу после
открывающих `"""` идёт перевод строки, строка выравнивается: этот перевод строки
отбрасывается, строка с закрывающими `"""` отбрасывается, если в ней только пробелы, а у
остальных строк убирается общий отступ (его определяют непустые строки и отступ закрывающих
кавычек). Иначе текст берётся как есть.

```upsil
fun prompt(doc) {
    return """
        Перескажи текст в трёх пунктах.
          Текст: "{doc}"
        """
}
print(prompt("..."))
```
```output
Перескажи текст в трёх пунктах.
  Текст: "..."
```

**Сырые строки** `r"..."` и `r"""..."""` берут текст как есть: обратная косая черта и
фигурные скобки в них — обычные символы, escape-последовательностей и интерполяции нет.
Удобно для регулярных выражений и путей Windows. Внутри `r"..."` не может быть `"`, внутри
`r"""..."""` — `"""`; многострочная сырая строка не выравнивается.

```upsil
print(r"\d{4}-\d{2}", r"C:\Users\max", len(r"\n"))
```
```output
\d{4}-\d{2} C:\Users\max 2
```

### 2.7. Операторы и знаки

```text
+  -  *  /  %  **  @
== != <  <= >  >=
=  += -= *= /= %=
.. ..=  =>  ->  .  ,  :  ;  ?
( ) [ ] { }
```

`&&`, `||`, `!`, `#` и `'` — ошибки с подсказкой (`and`, `or`, `not`, `//`, `"`).
`?` допустим только после типа (`int?`).

## 3. Грамматика (EBNF)

Обозначения: `{ x }` — ноль или больше повторений, `[ x ]` — необязательная часть,
`|` — выбор. `NAME`, `NUMBER`, `STRING`, `NEWLINE` — лексемы из раздела 2.

```ebnf
program       = { separator } { statement { separator } } ;
separator     = NEWLINE | ";" ;

statement     = var_decl | destruct_decl | resource_decl | fun_decl | class_decl | model_decl
              | if_stmt | while_stmt | for_stmt | try_stmt | with_stmt
              | "return" [ values ] | "break" | "continue"
              | "throw" [ expression ] | "assert" expression [ "," expression ]
              | import_stmt | assignment | expression ;
(* Простые инструкции (все, кроме fun, class, model, if, while, for, try, with) должны
   заканчиваться separator, "}" или концом файла. *)
values        = expression { "," expression } ;             (* два и больше — кортеж *)

block         = "{" { separator } { statement { separator } } "}" ;

var_decl      = ( "val" | "var" ) NAME [ ":" type ] [ "=" expression ] ;
              (* у val значение обязательно, кроме полей класса *)
destruct_decl = ( "val" | "var" ) "(" NAME { "," NAME } [ "," ] ")" "=" values ;
resource_decl = ( "llm" | "vector_store" ) NAME [ "=" expression ] ;
type          = NAME { "." NAME } [ "[" type { "," type } "]" ] [ "?" ] ;

fun_decl      = "fun" NAME "(" [ params ] ")" [ "->" type ] block ;
params        = param { "," param } [ "," ] ;
param         = NAME [ ":" type ] [ "=" expression ] ;

class_decl    = "class" NAME "{" { separator } { var_decl | fun_decl | separator } "}" ;
model_decl    = "model" NAME "{" { separator } { var_decl | fun_decl | graph_decl | separator } "}" ;
graph_decl    = "graph" NAME "(" [ params ] ")" [ "->" type ] block ;

if_stmt       = "if" expression block [ "else" ( if_stmt | block ) ] ;
while_stmt    = "while" expression block ;
for_stmt      = "for" "(" loop_target "in" expression ")" block
              | "for" loop_target "in" expression block ;
loop_target   = NAME { "," NAME } | "(" NAME { "," NAME } ")" ;
try_stmt      = "try" block { catch_clause } [ "finally" block ] ;   (* хотя бы один catch или finally *)
catch_clause  = "catch" [ "(" NAME [ ":" NAME { "." NAME } ] ")" ] block ;
with_stmt     = "with" ( with_items | "(" with_items ")" ) block ;
with_items    = expression [ "as" NAME ] { "," expression [ "as" NAME ] } ;

import_stmt   = "import" NAME [ "." NAME ] [ "as" NAME ]
              | "import" "py" STRING [ "as" NAME ]
              | "import" STRING [ "as" NAME ] ;                     (* другой файл .upl *)

assignment    = targets "=" values
              | target ( "+=" | "-=" | "*=" | "/=" | "%=" ) expression ;
targets       = target { "," target } | "(" target { "," target } ")" ;
target        = NAME | postfix "." NAME | postfix "[" subscripts "]" ;

expression    = or_expr ;
or_expr       = and_expr { "or" and_expr } ;
and_expr      = not_expr { "and" not_expr } ;
not_expr      = "not" not_expr | comparison ;
comparison    = range_expr [ comp_op range_expr ] ;          (* без цепочек *)
comp_op       = "==" | "!=" | "<" | "<=" | ">" | ">=" | "in" | "not" "in" ;
range_expr    = additive [ ( ".." | "..=" ) additive ] ;
additive      = term { ( "+" | "-" ) term } ;
term          = unary { ( "*" | "/" | "%" | "@" ) unary } ;
unary         = ( "-" | "+" ) unary | power ;
power         = postfix [ "**" unary ] ;                      (* правоассоциативно *)
postfix       = primary { call | "[" subscripts "]" | "." NAME } ;
call          = "(" [ argument { "," argument } [ "," ] ] ")" ;
argument      = [ NAME "=" ] expression ;                     (* именованные — после позиционных *)
subscripts    = subscript { "," subscript } [ "," ] ;
subscript     = expression | [ expression ] ":" [ expression ] [ ":" [ expression ] ] ;
primary       = NUMBER | STRING | "true" | "false" | "null" | NAME
              | "(" expression ")" | tuple | list | dict | prompt
              | if_expr | lambda | list_comp | dict_comp | gen_expr ;
tuple         = "(" expression "," [ expression { "," expression } [ "," ] ] ")" ;
list          = "[" [ expression { "," expression } [ "," ] ] "]" ;
dict          = "{" [ expression ":" expression { "," expression ":" expression } [ "," ] ] "}" ;
prompt        = "[" expression [ "," "system" ":" expression ] "]" "=>" expression
                [ "->" "json" [ "(" expression ")" ] ] ;
if_expr       = "if" "(" expression ")" expression "else" expression ;
lambda        = ( NAME | "(" [ NAME [ ":" type ] { "," NAME [ ":" type ] } ] ")" ) "=>" expression ;
list_comp     = "[" expression comp_for { comp_for } "]" ;
dict_comp     = "{" expression ":" expression comp_for { comp_for } "}" ;
gen_expr      = "(" expression comp_for { comp_for } ")" ;
              (* единственным аргументом вызова — без своих скобок: sum(x for x in xs) *)
comp_for      = "for" ( loop_target "in" expression | "(" loop_target "in" expression ")" )
                { "if" expression } ;
```

`if`-выражение и лямбда захватывают всё выражение справа: `if (c) 1 else 2 + 3` — это
`if (c) 1 else (2 + 3)`, а `x => x + 1` возвращает `x + 1`. Чтобы использовать их внутри
большего выражения, возьмите их в скобки.

Правое выражение промпта (после `=>`) — полное выражение: `[m] => "a" + b` отправляет
модели `"a" + b`. Чтобы использовать ответ внутри большего выражения, возьмите промпт в
скобки: `([m] => "Да или нет?") == "да"`.

## 4. Выражения

### 4.1. Приоритет и ассоциативность

От слабого к сильному:

| Уровень | Операторы | Ассоциативность |
|---|---|---|
| 1 | `or` | левая |
| 2 | `and` | левая |
| 3 | `not x` | префиксный |
| 4 | `== != < <= > >= in` `not in` | нет (цепочки запрещены) |
| 5 | `..` `..=` | нет |
| 6 | `+ -` | левая |
| 7 | `* / % @` | левая |
| 8 | `-x` `+x` | префиксные |
| 9 | `**` | правая; сильнее унарного минуса слева: `-2 ** 2 == -4` |
| 10 | `f(x)` `a[i]` `a[i:j]` `a.b` | постфиксные |

```upsil
print((1 + 2) * 3, 1 + 2 * 3, 2 ** 3 ** 2, -2 ** 2, 10 - 4 - 3)
print(not 1 == 2, true or false and false, 3 in 0..5)
```
```output
9 7 512 -4 3
true true true
```

Цепочки сравнений — ошибка компиляции:

```upsil-error
val x = 5
print(0 < x < 10)
```
```output
example.upl:2:13: ошибка: сравнения нельзя записывать цепочкой: пишите a < b and b < c
  2 | print(0 < x < 10)
    |             ^
```

### 4.2. Литералы

`42`, `3.14`, `"строка"`, `true`, `false`, `null`, список `[1, 2, 3]`, словарь
`{"ключ": "значение"}`. В списках, словарях, вызовах и параметрах допустима запятая после
последнего элемента. Пустые `{}` — пустой словарь.

### 4.3. Арифметика

- `+ - *` — как обычно; `+` соединяет строки и списки. Строку с числом `+` не соединяет —
  используйте интерполяцию или `str(x)`.
- `/` — всегда дробное деление: `7 / 2 == 3.5`, `4 / 2 == 2.0`.
- Целочисленного деления оператором нет, потому что `//` начинает комментарий: пишите
  `div(a, b)` (округление вниз).
- `%` — остаток, знак как у делителя (как в Python): `-7 % 3 == 2`.
- `**` — степень; `@` — матричное умножение (для тензоров и массивов).

```upsil
print(7 / 2, div(7, 2), -7 % 3, 2 ** 10, "ab" + "cd", [1] + [2])
```
```output
3.5 3 2 1024 abcd [1, 2]
```

### 4.4. Сравнения

`== != < <= > >=` сравнивают значения, `in` и `not in` проверяют вхождение (в строку,
список, словарь, диапазон). Сравнение с `null` (`x == null`, `x != null`) проверяет, пусто
ли значение.

### 4.5. Логика и истинность

`and` и `or` вычисляются лениво и возвращают один из операндов (как в Python):
`null or "по умолчанию"` даёт `"по умолчанию"`. `not x` даёт `true` или `false`.

Ложны: `false`, `null`, `0`, `0.0`, `""`, `[]`, `{}`; остальные значения истинны.

```upsil
val name = null
print(name or "гость", 0 and 5, not "")
```
```output
гость 0 true
```

### 4.6. Диапазоны

`a..b` — целые числа от `a` до `b` **не включая** `b`; `a..=b` — включая `b`. Диапазон
можно перебирать в `for`, проверять `in`, превращать в список `list(0..3)`.
Если `a >= b`, диапазон `a..b` пуст.

```upsil
print(list(0..3), list(1..=3), 5 in 1..5, list(3..0))
```
```output
[0, 1, 2] [1, 2, 3] false []
```

### 4.7. Вызовы, индексы, срезы, атрибуты

- Вызов: `f(1, 2)`, именованные аргументы `f(1, sep = "-")`; позиционный аргумент после
  именованного и повтор имени — ошибки компиляции.
- Индекс: `xs[0]`, `xs[-1]` (с конца), `d["ключ"]`; несколько индексов через запятую
  (`t[0, 1]`) передаются как кортеж — удобно для тензоров.
- Срез: `xs[1:3]`, `xs[:2]`, `xs[::2]`.
- Атрибут: `obj.name`, метод: `s.strip()`.

```upsil
val xs = [10, 20, 30, 40]
print(xs[0], xs[-1], xs[1:3], xs[::2], "привет"[0:3])
print(sorted([3, 1, 2], reverse = true), ", ".join(["a", "b"]))
```
```output
10 40 [20, 30] [10, 30] при
[3, 2, 1] a, b
```

### 4.8. Промпт

`[m] => текст` — выражение, значение которого — ответ модели. Подробно в разделе 9.2.

### 4.9. Как значения превращаются в текст

`print`, `str(x)` и интерполяция `"{x}"` показывают значения так: `true`, `false`, `null`;
числа как в Python (`3.0`, `0.1`); строки без кавычек, а внутри списков и словарей — в
двойных кавычках; списки `[1, 2]`; словари `{"a": 1}`; диапазоны `0..3`; объекты классов
UpsiL — `Имя(поле=значение, ...)`. Остальные объекты (например, тензоры) показываются так,
как их показывает Python.

### 4.10. Кортежи

Кортеж — неизменяемая последовательность: `(1, "два")`, кортеж из одного значения — `(7,)`.
Функция может вернуть несколько значений через запятую — это кортеж: `return lo, hi`. Скобки
без запятой — просто группировка: `(1 + 2) * 3`.

```upsil
fun min_max(xs) {
    return min(xs), max(xs)
}
val pair = min_max([4, 2, 9])
print(pair, pair[0], (7,), len((1, 2, 3)))
```
```output
(2, 9) 2 (7,) 3
```

### 4.11. Условное выражение `if`

`if (условие) a else b` — значение `a`, если условие истинно, иначе `b`. Условие пишется в
скобках, ветка `else` обязательна; значения могут начинаться на следующей строке. Цепочка —
`if (a) x else if (b) y else z`.

```upsil
fun sign(n) {
    return if (n > 0) "+" else if (n < 0) "-" else "0"
}
val label = if (len([1, 2, 3]) > 2)
    "много"
    else "мало"
print(sign(5), sign(-2), sign(0), label)
```
```output
+ - 0 много
```

### 4.12. Лямбды

Лямбда — короткая безымянная функция из одного выражения: `x => x * 2`, `(a, b) => a + b`,
`() => 42`. Параметрам можно указать типы: `(s: str) => s.upper()`. Лямбда видит
переменные вокруг себя (как вложенная функция); её параметры изменять нельзя. Для
нескольких инструкций объявите обычную функцию `fun`.

```upsil
val double = x => x * 2
val words = ["банан", "яблоко", "киви"]
print(double(21), sorted(words, key = w => len(w)))
print(list(map(n => n * n, 1..=4)), list(filter(n => n % 2 == 0, 0..6)))
val templates = {"коротко": q => "Ответь одним словом: {q}"}
print(templates["коротко"]("столица Франции?"))
```
```output
42 ["киви", "банан", "яблоко"]
[1, 4, 9, 16] [0, 2, 4]
Ответь одним словом: столица Франции?
```

### 4.13. Генераторы списков и словарей

`[выражение for x in xs if условие]` строит список, `{ключ: значение for ...}` — словарь.
Цикл пишется в любой из двух форм `for` (со скобками и без), можно разложить пару и
перечислить несколько циклов и условий подряд. Переменные генератора видны только внутри
него.

Без квадратных скобок, единственным аргументом функции, генератор отдаёт значения по одному,
не собирая список: `sum(x * x for x in xs)`. В других местах такой генератор берут в
круглые скобки: `(x for x in xs)`.

```upsil
val xs = [3, 1, 4, 1, 5]
print([x * x for x in xs if x > 1])
print({w: len(w) for w in ["аб", "в"]})
print([a * b for a in 1..=2 for b in 1..=3])
print(sum(x for x in xs), [(i, c) for (i, c) in enumerate("аб")])
```
```output
[9, 16, 25]
{"аб": 2, "в": 1}
[1, 2, 3, 2, 4, 6]
14 [(0, "а"), (1, "б")]
```

## 5. Инструкции

### 5.1. `val` и `var`

`val` объявляет неизменяемую переменную (присвоить ей новое значение нельзя — это ошибка
компиляции), `var` — изменяемую. У `val` значение обязательно; `var x` без значения
получает `null`. Можно указать тип: `val n: int = 1`, `var names: list[str]`, `var t: int?`.
Типы записываются и попадают в аннотации сгенерированного Python, но во время выполнения не
проверяются; `upsil check` сообщает только об очевидных несовпадениях литералов
(`val n: int = "один"`). Известные ему типы: `int`, `float` (принимает и целые), `str`
(или `string`), `bool`, `list`, `dict`.

`val` запрещает только новое присваивание: содержимое списка или словаря в `val` менять
можно (`xs.append(1)`, `d["k"] = 2`).

```upsil-error
val x = 1
x = 2
```
```output
example.upl:2:1: ошибка: нельзя изменить val 'x' (объявлено в строке 1); объявите через var
  2 | x = 2
    | ^
```

### 5.2. Присваивание

`x = выражение`, `obj.поле = ...`, `xs[i] = ...`, `xs[1:3] = [...]`. Составные формы
`+= -= *= /= %=`. Присваивать можно только объявленной переменной (`var`), полю или
элементу. Присваивание — инструкция, а не выражение: `a = b = 1` не допускается.

### 5.3. `if`

```upsil
fun size(n) {
    if n > 10 {
        return "большое"
    } else if n > 1 {
        return "среднее"
    } else {
        return "маленькое"
    }
}
print(size(50), size(5), size(0))
```
```output
большое среднее маленькое
```

Условие можно взять в скобки (`if (x > 1) { ... }`), фигурные скобки обязательны.

### 5.4. `while`

`while условие { ... }` повторяет блок, пока условие истинно.

### 5.5. `for`

Цикл перебирает любую последовательность: диапазон, список, строку, словарь (ключи), а
также результаты `enumerate`, `zip`, `d.items()`. Две равноценные формы — со скобками и
без; можно сразу разложить пару на две переменные:

```upsil
for (i in 0..3) { print(i, end = " ") }
print()
for ch in "аб" { print(ch) }
for (k, v) in {"a": 1, "b": 2}.items() { print("{k}={v}") }
for i, word in enumerate(["x", "y"]) { print(i, word) }
```
```output
0 1 2 
а
б
a=1
b=2
0 x
1 y
```

Переменные цикла видны только в теле цикла и не могут изменяться.

### 5.6. `break` и `continue`

`break` выходит из ближайшего цикла, `continue` переходит к следующему шагу. Вне цикла (в
том числе во вложенной функции внутри цикла) — ошибка компиляции.

### 5.7. `return`

`return выражение` возвращает значение из функции, `return` без значения (или конец
функции) возвращает `null`. `return` вне функции — ошибка компиляции. Выражение должно
начинаться на той же строке, что и `return`.

### 5.8. Распаковка

`val (a, b) = пара` объявляет сразу несколько переменных из последовательности (кортежа,
списка, строки); `var (x, y) = ...` — изменяемые. Число имён должно совпадать с числом
значений. Изменяемым переменным можно присвоить несколько значений сразу: `a, b = b, a`.

```upsil
val (name, age) = ("Аня", 30)
var (a, b) = 1, 2
a, b = b, a
print(name, age, a, b)
```
```output
Аня 30 2 1
```

### 5.9. Ошибки: `try`, `catch`, `finally`, `throw`

`throw значение` останавливает выполнение с ошибкой. Значение — текст сообщения или объект
ошибки: `throw "нет файла"`, `throw ValueError("плохое число")`.

`try { ... } catch (e) { ... }` перехватывает ошибку, случившуюся в блоке `try`, и
выполняет блок `catch`; в `e` — пойманная ошибка (`"{e}"` — её текст). Можно указать тип
и написать несколько `catch` подряд — сработает первый подходящий: `catch (e: ValueError)`,
`catch (e: llm.FormatError)`. `catch (e)` и `catch (e: Error)` ловят любую ошибку
программы (но не Ctrl-C и не `sys.exit`); `catch { ... }` без скобок — то же без имени.
Блок `finally { ... }` выполняется всегда: и после успеха, и после ошибки. После `try`
нужен хотя бы один `catch` или `finally`.

Внутри `catch` можно написать `throw` без значения — пойманная ошибка полетит дальше.
Пойманную ошибку нельзя изменить, а видна она только в своём блоке `catch`.

```upsil
fun parse_age(text) {
    val n = int(text)
    if n < 0 {
        throw "возраст не может быть отрицательным: {n}"
    }
    return n
}
for (text in ["30", "abc", "-5"]) {
    try {
        print("возраст:", parse_age(text))
    } catch (e: ValueError) {
        print("не число:", text)
    } catch (e) {
        print("ошибка:", e)
    } finally {
        print("проверили", text)
    }
}
```
```output
возраст: 30
проверили 30
не число: abc
проверили abc
ошибка: возраст не может быть отрицательным: -5
проверили -5
```

Ошибка, которую никто не поймал, останавливает программу:

```upsil
fun check(n) {
    if n < 0 { throw "отрицательное число: {n}" }
    return n
}
check(-5)
```
```output
Ошибка выполнения (последний вызов — внизу):
  example.upl:5, в <программа>
    check(-5)
  example.upl:2, в check
    if n < 0 { throw "отрицательное число: {n}" }
               ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
ошибка: отрицательное число: -5
```

```upsil-error
throw
```
```output
example.upl:1:1: ошибка: 'throw' без значения повторно бросает пойманную ошибку и допустим только внутри catch { }; иначе пишите throw "что случилось"
  1 | throw
    | ^^^^^
```

### 5.10. `with`

`with выражение as имя { ... }` выполняет блок внутри контекста — объекта, который
подготавливает что-то перед блоком и убирает после, даже если в блоке случилась ошибка.
Так работают `nn.no_grad()` (вычисления без градиентов), `nn.evaluating(net)` и объекты
Python с методами `__enter__`/`__exit__`. `as имя` необязательно; несколько контекстов
перечисляются через запятую, весь список можно взять в скобки. Имя из `as` видно только в
блоке, изменять его нельзя.

```upsil
class Step {
    val name: str
    fun __enter__() {
        print("начало:", name)
        return self
    }
    fun __exit__(kind, value, trace) {
        print("конец:", name)
        return false
    }
}
with Step("загрузка") as s, Step("разбор") {
    print("работаем:", s.name)
}
```
```output
начало: загрузка
начало: разбор
работаем: загрузка
конец: разбор
конец: загрузка
```

### 5.11. `assert`

`assert условие` проверяет условие и, если оно ложно, останавливает программу с ошибкой
«проверка не прошла: условие»; `assert условие, сообщение` — со своим сообщением. Ошибку
ловит `catch (e: AssertionError)`. Проверки работают всегда (даже под `python -O`) и
удобны в тестах (`upsil test`, раздел 13.2).

```upsil
val scores = [0.9, 0.7]
assert len(scores) == 2
try {
    assert min(scores) > 0.8, "есть слабые ответы: {min(scores)}"
} catch (e: AssertionError) {
    print(e)
}
```
```output
есть слабые ответы: 0.7
```

## 6. Функции

```upsil
fun greet(name: str, greeting = "Привет", punct = "!") -> str {
    return "{greeting}, {name}{punct}"
}
print(greet("Аня"))
print(greet("Боря", punct = "?"))
print(greet(greeting = "Здравствуй", name = "Вика"))
```
```output
Привет, Аня!
Привет, Боря?
Здравствуй, Вика!
```

- Параметры неизменяемы (как `val`). Типы параметров и результата необязательны.
- Значения по умолчанию вычисляются **при каждом вызове** и могут использовать предыдущие
  параметры: `fun area(w, h = w)`. Параметр без значения по умолчанию не может идти после
  параметра со значением.
- При прямом вызове функции UpsiL компилятор проверяет число аргументов и имена
  именованных аргументов.
- Функции могут быть вложенными и видят переменные внешних функций (замыкания); `var`
  внешней функции можно изменять.
- Функция может вызывать функции, объявленные ниже в файле, и саму себя.

```upsil
fun counter() {
    var n = 0
    fun next_value() {
        n += 1
        return n
    }
    return next_value
}
val c = counter()
c()
print(c(), c())
```
```output
2 3
```

**Ограничение v0.2.** Замыкание запоминает переменную, а не её значение (как в Python):
функции, созданные в теле цикла, видят последнее значение переменной цикла.

## 7. Области видимости

- Блок `{ }` задаёт область видимости. Имя видно от объявления до конца блока; использовать
  его раньше в той же функции — ошибка компиляции.
- Тело функции видит все имена блоков, в которых функция объявлена, включая объявленные
  ниже: поэтому функции могут вызывать друг друга в любом порядке. На верхнем уровне файла
  код выполняется сверху вниз, и вызов функции до её объявления — ошибка компиляции.
- Повторное объявление имени в том же блоке — ошибка. Объявить имя, которое видно из
  внешнего блока той же функции (перекрыть его), тоже нельзя. Внутри функции можно заново
  использовать имена верхнего уровня и параметры других функций; соседние блоки могут
  объявлять одинаковые имена.
- Встроенные функции (раздел 11) можно перекрыть своими объявлениями.
- `class` и `model` объявляются только на верхнем уровне, `import` — тоже.
- Пойманная ошибка `catch (e)`, имя из `with ... as x`, переменные генераторов и параметры
  лямбд видны только в своём блоке или выражении и не изменяются.

Компилятор находит эти ошибки до запуска и сообщает обо всех сразу:

```upsil-error
val limit = 10
fun check(n) {
    if n > lmit {
        print("много")
    }
    return result
}
```
```output
example.upl:3:12: ошибка: неизвестное имя 'lmit'; может быть, 'limit'?
  3 |     if n > lmit {
    |            ^^^^
example.upl:6:12: ошибка: неизвестное имя 'result'
  6 |     return result
    |            ^^^^^^
```

## 8. Классы и модели

### 8.1. `class`

Тело класса содержит только поля (`val`/`var`) и методы (`fun`).

- Поле **без значения** становится параметром конструктора (в порядке объявления); поле со
  значением получает его при создании объекта (значение вычисляется для каждого объекта
  заново и может использовать поля, объявленные выше).
- Внутри методов к полям и методам можно обращаться по имени (`count += 1`) или через
  `self` (`self.count`). `self` в список параметров не пишется.
- Поле `val` нельзя изменить после создания объекта.
- Наследования нет. Объект показывается как `Имя(поле=значение, ...)`.

```upsil
class Counter {
    val name: str
    var count = 0

    fun inc(by = 1) {
        count += by
        return self
    }

    fun label() {
        return "{name}: {count}"
    }
}

val c = Counter("клики")
c.inc().inc(by = 5)
print(c.label(), c.count)
print(c)
```
```output
клики: 6 6
Counter(name="клики", count=6)
```

### 8.2. `model`

`model` объявляет нейросеть — подкласс `torch.nn.Module` (нужен PyTorch, раздел 9.4).
Поля становятся слоями и регистрируются в конструкторе, поля без значения — параметрами
конструктора, как у классов. Метод `forward` обязателен; его можно объявить словом `graph`
(это то же, что `fun`, но подчёркивает, что метод описывает вычисление). Внутри методов слои
вызываются по имени: `l1(x)` означает `self.l1(x)`.

```upsil
import nn

model Net {
    val hidden: int
    val l1 = nn.Linear(4, hidden)
    val l2 = nn.Linear(hidden, 2)

    graph forward(x) {
        return l2(nn.relu(l1(x)))
    }
}
```

Этот код становится таким Python (`upsil build`):

```python
class Net(_upsil_nn.Module):

    def __init__(self, hidden: int):
        super().__init__()
        self.hidden = hidden
        self.l1 = nn.Linear(4, self.hidden)
        self.l2 = nn.Linear(self.hidden, 2)

    def forward(self, x):
        return self.l2(nn.relu(self.l1(x)))
```

Без PyTorch программа останавливается на строке `model` с сообщением «PyTorch не
установлен…».

## 9. ИИ: модели, промпты, поиск

### 9.1. Модели: `llm`

Модель — объект `llm.Model`, который обращается к серверу с API, совместимым с OpenAI
(`/v1/chat/completions`). Объявить её можно обычной переменной или формой ресурса:

```upsil
import llm

val a = llm.Model("qwen3.5-4b")        // модель с явным именем
llm b = llm.Model(temperature = 0.2)   // то же в форме ресурса
llm c                                  // модель по умолчанию
```

Форма `llm имя = выражение` — это `val`, который вдобавок проверяет во время выполнения,
что значение — модель; `llm имя` без значения создаёт `llm.Model()`. Создание модели не
обращается к серверу: запрос уходит при первом вопросе.

Адрес сервера — первое найденное из:

1. `llm.Model(url = "...")`;
2. переменной окружения `UPSIL_LLM_URL`;
3. `[llm] url` в `~/.config/upsil/config.toml` (или в файле из `UPSIL_CONFIG`; учитывается
   `XDG_CONFIG_HOME`);
4. `http://127.0.0.1:8080/v1` — локальный сервер СОС (`sos models serve`).

Имя модели: аргумент `llm.Model("имя")`, иначе `UPSIL_LLM_MODEL`, иначе `[llm] model` в
файле настроек, иначе первая модель из списка сервера (`/v1/models`). Ключ API не
обязателен: `UPSIL_LLM_KEY` или `OPENAI_API_KEY` (для облачных серверов). Время ожидания —
`timeout` (секунды, по умолчанию 120 или `[llm] timeout`).

```toml
# ~/.config/upsil/config.toml
[llm]
url = "http://127.0.0.1:8080/v1"
model = "qwen3.5-4b"
timeout = 120

[rag]
embed_model = "bge-m3"
backend = "auto"
```

Если сервер не отвечает, программа останавливается с понятной ошибкой:

```text
ошибка: Локальная модель не отвечает (127.0.0.1:8080). В СОС: sos models serve
```

Методы модели: `ask`, `chat`, `stream`, `embed`, `models` (раздел 12). Блоки размышлений
`<think>...</think>`, которые печатают некоторые локальные модели, из ответов удаляются.

### 9.2. Оператор промпта `=>`

```upsil
import llm

llm m = llm.Model()
val doc = "UpsiL — язык для ИИ-скриптов."
val short = [m] => "Перескажи в одном предложении: {doc}"
val terse = [m, system: "Отвечай одним словом"] => "Столица Франции?"
val data = [m] => "Верни JSON с полями name и age для: Аня, 30 лет" -> json
print(short, terse, data["name"])
```

- `[m] => текст` отправляет модели `m` одно сообщение пользователя и возвращает ответ
  (строку). Текст — любое выражение; если это не строка, он превращается в текст, как в
  `print`.
- `[m, system: s] => текст` добавляет системный промпт `s`.
- `-> json` просит ответ в JSON: к системному промпту добавляется требование ответить
  только JSON, а если сервер поддерживает `response_format`, он тоже используется. Ответ
  разбирается (обрамление ```json и лишний текст вокруг допускаются) и возвращается как
  словарь или список; если это не JSON — ошибка выполнения.
- `-> json(форма)` описывает, какой JSON нужен, и проверяет ответ (раздел 9.5).
- Если ответ — не тот JSON, модели объясняют, что не так, и спрашивают ещё раз
  (`json_retries` раз, по умолчанию 1); не помогло — ошибка `llm.FormatError`, которую можно
  поймать: `catch (e: llm.FormatError)`, текст ответа — в `e.reply`.
- `m` может быть любым объектом с методом `ask(text, system, json)`, например своим классом.
- Интерполяция в тексте промпта вставляет данные как текст: содержимое переменных не
  выполняется и не интерпретируется как шаблон.

### 9.3. Поиск по документам: `vector_store`

```upsil
import rag

vector_store db = rag.VectorStore()
db.add("Париж — столица Франции.", {"тема": "география"})
db.add("Луна обращается вокруг Земли.")
for (hit in db.search("вокруг чего обращается Луна?", k = 1)) {
    print(hit.text)
}
```

`vector_store db` без значения создаёт `rag.VectorStore()`; форма с `=` проверяет, что
значение — хранилище.

Поиск работает одним из двух способов:

- **эмбеддинги** (`backend = "embeddings"`): векторы текстов берутся у сервера моделей
  (`POST /v1/embeddings`), близость — косинусная, считается на чистом Python;
- **по словам** (`backend = "bm25"`): BM25 с простой нормализацией русских и английских
  окончаний.

По умолчанию (`backend = "auto"`) хранилище пробует эмбеддинги при первом добавлении, а если
сервер их не даёт (например, llama.cpp запущен без `--embeddings`) или не отвечает, один раз
пишет об этом в stderr и дальше ищет по словам. Так же оно поступает, если эмбеддинги
пропали позже. Выбрать способ явно: `rag.VectorStore(backend = "bm25")`, модель
эмбеддингов: `rag.VectorStore("bge-m3")` или `[rag] embed_model`.

Результат `search` — список найденного, лучшие первыми; у каждого элемента есть `text`,
`score`, `meta` и `id` (`hit.text` или `hit["text"]`). По словам находятся только
документы, где есть хотя бы одно слово запроса. `add_dir` добавляет файлы папки (по
умолчанию `*.md`, рекурсивно, без скрытых папок), разбивая их на фрагменты примерно по
1000 символов; в `meta` записываются `source` (путь внутри папки) и `chunk`.
`save(путь)` и `rag.VectorStore.load(путь)` сохраняют и загружают хранилище в JSON.
Хранилище целиком находится в памяти: оно рассчитано на заметки и документы, а не на
миллионы фрагментов.

### 9.4. Нейросети: `nn`

`import nn` даёт доступ к PyTorch: `nn.X` ищется в `torch.nn`, затем в
`torch.nn.functional`, затем в `torch` (`nn.Linear`, `nn.relu`, `nn.tensor`, `nn.optim.Adam`,
`nn.manual_seed`, …); `nn.torch` — сам модуль `torch`; `nn.available()` — установлен ли
PyTorch. PyTorch загружается при первом обращении; установить его:
`pip install torch` или `uv tool install 'upsil[nn]'`. Полный пример —
[examples/neural_net.upl](../examples/neural_net.upl).

### 9.5. Форма ответа и пачки запросов

Форма — обычное значение UpsiL, которое описывает нужный JSON:

| Форма | Что должно прийти |
|---|---|
| `str`, `int`, `float`, `bool` | строка, целое число, число (целое тоже подходит), true/false |
| `list`, `dict` | любой список, любой объект |
| `[T]` | список, каждый элемент которого подходит под `T` |
| `["a", "b", "c"]` | одно из перечисленных значений |
| `{"ключ": T, "заметка?": T}` | объект с этими полями; `?` в конце — поле необязательно |
| `null` | null |

`[m] => текст -> json(форма)` и `m.ask(текст, schema = форма)` добавляют форму к
системному промпту, а серверу, который умеет ограничивать вывод (llama.cpp, OpenAI),
передают её как JSON Schema. Ответ проверяется; числа приводятся, если это ничего не
теряет (`3.0` для `int` становится `3`); лишние поля остаются.

`m.ask_all(список_вопросов, ...)` задаёт много вопросов сразу (`workers` параллельно, по
умолчанию 4) и возвращает ответы в том же порядке. Параметры те же, что у `ask`
(`system`, `json`, `schema`…); `errors = "null"` ставит `null` вместо ответа, который не
удалось получить, и продолжает, вместо того чтобы остановиться на первой ошибке.

```upsil
import llm

llm m = llm.Model(temperature = 0.0)
val shape = {"label": ["pos", "neg", "neu"], "score": float}
val reviews = ["Отличный ноутбук", "Экран сломался через неделю"]
val answers = m.ask_all(["Оцени тональность отзыва: {r}" for r in reviews], schema = shape,
                        errors = "null")
for (text, a) in zip(reviews, answers) {
    if a != null {
        print("{a["label"]} {a["score"]:.1f}  {text}")
    }
}
```

## 10. Импорт

```upsil
import llm                       // модуль UpsiL
import nn.functional as F        // часть модуля под своим именем
import py "numpy" as np          // модуль Python
import py "os.path"              // даёт имя os
```

Модули UpsiL: `llm`, `rag`, `nn`, `fs`, `http`, `json`, `ui`, `sys`, `math`, `time`,
`random`, `csv`, `re` (раздел 12). `import x.y as z` связывает `z` с `x.y`; глубже одного уровня
импортировать нельзя. `import py "имя"` подключает любой модуль Python (без `as` имя
связывается с первой частью пути, как в Python). Импорт допускается только на верхнем
уровне файла.

**Другие файлы UpsiL.** `import "helpers.upl" as h` выполняет файл `helpers.upl` (путь
считается от папки программы) и связывает имя `h` с его верхним уровнем: функции, классы и
переменные файла становятся атрибутами `h.shout(...)`. Без `as` имя берётся из имени файла:
`import "lib/data.upl"` даёт `data`. Короткая запись `import helpers` находит `helpers.upl`
рядом с программой, если так не называется модуль UpsiL. Каждый файл выполняется один раз,
сколько бы раз его ни импортировали; если файл не найден, это ошибка компиляции; циклический
импорт (`a.upl` → `b.upl` → `a.upl`) — ошибка выполнения. Модуль Python, лежащий рядом со
скриптом, подключается через `import py`.

## 11. Встроенные функции

Доступны без импорта:

| Функция | Что делает |
|---|---|
| `print(x, ..., sep = " ", end = "\n")` | печатает значения так, как описано в 4.9; если `end` без перевода строки, вывод появляется сразу |
| `input(prompt = "")` | строка с клавиатуры; `null` в конце ввода (Ctrl-D) |
| `str(x)` | текст значения, как у `print`; `isinstance(s, str)` работает |
| `div(a, b)` | целочисленное деление с округлением вниз |
| `error(message)` | останавливает программу с ошибкой `message` |
| `int float bool len range list dict set tuple min max sum abs round sorted reversed enumerate zip map filter any all chr ord format isinstance divmod pow iter next hash` | как в Python |

Типы ошибок для `catch (e: ...)` и `throw`: `Error` (любая ошибка программы), `ValueError`,
`TypeError`, `KeyError`, `IndexError`, `ZeroDivisionError`, `FileNotFoundError`,
`TimeoutError`, `RuntimeError`, `AssertionError`; у модулей свои: `llm.Error`,
`llm.FormatError`.

Остальные функции Python (`open`, `eval`, `getattr`…) встроенными в UpsiL не являются;
при необходимости их можно получить через `import py "builtins"`.

## 12. Модули

**llm** — модели (9.1, 9.2).
`llm.Model(name = null, url = null, api_key = null, timeout = null, temperature = null,
max_tokens = null, system = null)`. Методы: `ask(prompt, system = null, json = false,
temperature = null, max_tokens = null)` — ответ на один вопрос; `chat(messages, ...)` —
ответ на переписку, `messages` — список `{"role": ..., "content": ...}` (роли `system`,
`user`, `assistant`); `stream(prompt_or_messages, ...)` — ответ по кусочкам, для `for`;
`embed(texts, model = null)` — векторы; `models()` — список моделей сервера. Поля `name`,
`url`. Функции `llm.models()`, `llm.default_url()`. Пока сервер загружает модель (HTTP 503),
запрос повторяется в пределах `timeout`.

Модели 0.3: `llm.Model(..., json_retries = 1)`; у `ask` и `chat` параметр `schema` (9.5);
`ask_all(prompts, system = null, json = false, schema = null, workers = 4, errors = "raise")`.
Ошибки: `llm.Error` (любая ошибка модели), `llm.FormatError` (ответ — не тот JSON; поле
`reply`).

**rag** — хранилище документов (9.3).
`rag.VectorStore(model = null, backend = "auto", url = null, chunk_size = 1000)`; методы
`add(text, meta = null)` (возвращает `id`), `add_dir(path, glob = "*.md")` (возвращает число
фрагментов), `search(query, k = 3)`, `context(query, k = 3)` (тексты найденного одной строкой
для промпта), `save(path)`; `rag.VectorStore.load(path)`; `len(db)`; поле `backend`.

**nn** — PyTorch (9.4) и помощники UpsiL:

- `nn.fit(model, x, y, epochs = 10, lr = 0.001, batch = 32, loss = null, optimizer = null,
  val = null, every = 1, device = null, shuffle = true, quiet = false)` — обучает модель и
  возвращает историю: список словарей `{"epoch", "loss", "val_loss", "val_accuracy"}`.
  По умолчанию Adam с `lr`; функция потерь — перекрёстная энтропия, если в `y` номера
  классов, и MSE, если числа (для вероятностей 0/1 передайте
  `loss = nn.binary_cross_entropy`). `val = (x_val, y_val)` добавляет проверку на отложенных
  данных. Каждые `every` эпох печатается строка «эпоха 20/60 · loss 0.2928 · val 0.2654 ·
  точность 92.5%». Ctrl-C останавливает обучение досрочно, выученное сохраняется. После
  обучения модель в режиме оценки.
- `nn.batches(x, y, ..., size = 32, shuffle = false, drop_last = false)` — мини-пакеты
  тензоров одной длины: `for ((xb, yb) in nn.batches(x, y, size = 64, shuffle = true))`.
- `nn.evaluating(model)` — контекст для `with`: режим оценки и без градиентов внутри,
  прежний режим после.
- `nn.accuracy(model, x, y)` — доля верных ответов классификатора (0.0–1.0).
- `nn.auto_device()` — `"cuda"`, `"mps"` или `"cpu"`; `nn.count_params(model)` — сколько
  чисел учит модель.

Пример — [examples/spirals.upl](../examples/spirals.upl).

**csv** — таблицы: `read(path, sep = ",", header = true, numbers = false)` — строки файла:
словари по первой строке (или списки с `header = false`); `numbers = true` превращает числа
из текста в числа. `parse(text, ...)` — то же из строки. `write(path, rows, columns = null,
sep = ",")` пишет список словарей (столбцы — по ключам) или списков и возвращает число строк;
`stringify(rows, ...)` — то же в строку.

**re** — регулярные выражения (шаблоны удобно писать сырыми строками `r"..."`):
`test(pattern, text)` — есть ли совпадение; `find` — первое совпадение или `null`;
`find_all` — все совпадения (с одной группой `( )` — её текст, с несколькими — списки);
`groups` — группы первого совпадения или `null`; `replace(pattern, replacement, text)` —
замена на текст (`\1` — группа) или на результат функции от найденного;
`split(pattern, text)`; `escape(text)`. У всех — `ignore_case = true`.

```upsil
import re
val log = "10:02 WARN gpu 83C; 10:03 ERROR data"
print(re.find_all(r"(WARN|ERROR) (\w+)", log), re.replace(r"\d+C", t => "{int(t[:-1]) + 1}C", log))
```
```output
[["WARN", "gpu"], ["ERROR", "data"]] 10:02 WARN gpu 84C; 10:03 ERROR data
```

**fs** — файлы (текст в UTF-8): `read(path)`, `write(path, text)`, `append(path, text)`,
`lines(path)`, `exists(path)`, `is_file(path)`, `is_dir(path)`,
`list(path = ".", glob = "*")` (отсортированные пути относительно `path`; `"**/*.md"` — с
подпапками), `mkdir(path)` (с родительскими папками), `remove(path)` (файл),
`join(parts...)`, `dirname(path)`, `basename(path)`, `home()`, `cwd()`.

**http** — `get(url, headers = null, timeout = 30)` (текст), `get_json(url, ...)`,
`post(url, body = "", ...)`, `post_json(url, data, ...)` (отправляет JSON, возвращает
разобранный JSON или текст). Ошибки сети и HTTP останавливают программу с понятным
сообщением. Прокси из окружения используются, кроме локальных адресов.

**json** — `parse(text)`, `stringify(value, indent = null)`, `read(path)`,
`write(path, value, indent = 2)`.

**ui** — окно чата на tkinter: `ui.Window(title = "UpsiL", width = 600, height = 700,
echo = true)`; методы `add_message(text)` (можно вызывать из любого потока),
`on_submit(handler)` (обработчик получает текст и выполняется в фоновом потоке),
`show()`, `close()`. Нужны `python3-tk` и графический сеанс; без них — понятная ошибка.

**sys** — `args` (аргументы после имени файла), `script` (имя файла), `env(name,
default = null)`, `exit(code = 0)`, `platform`, `version` (версия UpsiL).

**math** — всё из модуля Python `math`: `sqrt`, `floor`, `ceil`, `log`, `sin`, `pi`, `e`,
`inf`, `gcd`…

**time** — `now()` (секунды с 1970 года), `monotonic()`, `sleep(seconds)`, `today()`
(`ГГГГ-ММ-ДД`), `format(fmt = "%Y-%m-%d %H:%M:%S", at = null)`.

**random** — `seed(x)`, `random()`, `randint(a, b)` (оба конца включены), `uniform(a, b)`,
`choice(xs)`, `sample(xs, k)`, `shuffle(xs)`. Не для паролей.

## 13. Компиляция, запуск и ошибки

### 13.1. Как работает компилятор

Текст → лексемы → дерево UpsiL → проверки (имена, `val`, `break`, `return`, число
аргументов…) → дерево Python (`ast`) с номерами строк и столбцов из `.upl` →
`compile(..., "файл.upl", "exec")` → выполнение. Текст программы нигде не выполняется как
строка кода Python.

### 13.2. Команды

| Команда | Что делает |
|---|---|
| `upsil run ФАЙЛ [АРГУМЕНТЫ...]` | компилирует и запускает; аргументы попадают в `sys.args`; `upsil ФАЙЛ.upl` — то же |
| `upsil run -` | читает программу из стандартного ввода |
| `upsil build ФАЙЛ [-o ВЫХОД]` | печатает сгенерированный Python или пишет его в `ВЫХОД` (никогда — рядом с исходником сам по себе и никогда поверх него) |
| `upsil check ФАЙЛ...` | ищет ошибки без запуска, включая несовпадения типов литералов |
| `upsil test [ПУТЬ...]` | запускает тесты: функции `fun test_...()` в файлах `test_*.upl` и `*_test.upl` (в указанных папках или в текущей, с подпапками) |
| `upsil repl` | интерактивный режим |
| `upsil version`, `upsil help` | версия и справка |

`python -m upsil` работает так же. Папка скрипта добавляется в путь импорта Python.

Коды выхода: `0` — успех, `1` — ошибка выполнения, `2` — ошибка компиляции, `64` — неверный
вызов (нет файла, неизвестная команда). `sys.exit(n)` завершает программу с кодом `n`.

`upsil test` сначала выполняет верхний уровень файла с тестами (импорты, объявления), затем
каждую функцию `test_...` в порядке файла. Тест прошёл, если функция завершилась; не прошёл,
если сработал `assert` или случилась ошибка — тогда показывается сообщение и строка:

```text
tests/test_text.upl
  ✓ test_words
  ✗ test_shout — лишний восклицательный знак  (tests/test_text.upl:6)
2 теста: 1 прошёл, 1 не прошёл (0.01 с)
```

Код выхода `upsil test`: `0` — все прошли, `1` — есть непрошедшие, `2` — ошибка компиляции
в файле с тестами, `64` — тестов не нашлось.

### 13.3. Сообщения об ошибках

Язык сообщений — русский, если `UPSIL_LANG`, `LC_ALL`, `LC_MESSAGES` или `LANG` (в этом
порядке; первая заданная) начинается с `ru`, иначе английский. Ошибка компиляции:

```text
hello.upl:12:5: ошибка: неожиданный токен ')' — ожидалось выражение
  12 | print(1 + )
     |           ^
```

Ошибка выполнения показывает только строки программы UpsiL (без внутренностей Python),
с указанием места, если его знает Python 3.11 и новее:

```upsil
fun main() {
    val x = 0
    print(1 / x)
}
main()
```
```output
Ошибка выполнения (последний вызов — внизу):
  example.upl:5, в <программа>
    main()
  example.upl:3, в main
    print(1 / x)
          ^^^^^
ZeroDivisionError: division by zero — деление на ноль
```

Если один и тот же вызов повторяется много раз подряд (глубокая рекурсия), он показывается
трижды, а дальше — строкой «тот же вызов повторяется ещё N раз». `UPSIL_TRACEBACK=python`
показывает полную трассировку Python.

### 13.4. REPL

`upsil repl` выполняет введённое сразу и показывает значения выражений (строки — в
кавычках). Ввод продолжается, пока не закрыта скобка или строка кончается оператором;
пустая строка завершает ввод. Имена можно объявлять заново. Выход — Ctrl-D или `:q`.

## 14. Чего нет в v0.3

Сознательно оставлено на потом: наследование классов, безымянные функции с блоком
(`fun (x) { ... }`; есть лямбды из одного выражения), вложенная распаковка
(`val (a, (b, c)) = ...`), безопасный вызов `?.` и оператор `?:`, статическая проверка
типов, асинхронность, форматирование кода (`fmt`), языковой сервер (LSP), компиляция в
машинный код (прототип на LLVM из v0.1 сохранён в истории git).
